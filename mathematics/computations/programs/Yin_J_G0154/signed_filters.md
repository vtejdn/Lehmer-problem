# Signed-unit rectification of nonsquare positive filter inputs

<a id="scope"></a>
## Exact arithmetic supply and its limits

[signed_filters.py](signed_filters.py) retains the bounded arithmetic tests for the [nonsquare multiplier proposal](../../../ledger/Yin_L_G0462_v7.md#signed-unit-rectification).
It computes eight signed conductor-layer norms of the fixed Lehmer trace polynomial and constructs exactly two positive multipliers at conductor 81, from filter indices \((1)\) and \((1,2)\).
Both are proved nonsquare in the integral trace order.
No unit descent, moment enumeration, polynomial-root computation or small-shell probability claim is part of this program.
The existing [baseline](readme.md), [balanced controls](balanced.md), [unit ball](unit_ball.md) and [square-root traversal](low_energy_shell.md) retain their separate scopes.

<a id="layer-norms"></a>
## Signed layer norms and the rectification boundary

Put \(V(t)=t^5+t^4-5t^3-5t^2+4t+3\) and \(F_i(t)=1+T_{3^{i-1}}(t)\), where \(T_a(z+z^{-1})=z^a+z^{-a}\).
The signed layer norm is \(A_i=\operatorname{Res}(F_i,V)\).
Starting with \(R_1=t\), use the degree-below-five recurrence
\[
 R_{i+1}=R_i^3-3R_i\pmod V,\qquad
                  A_i=-\operatorname{Res}(V,1+R_i).
\]
Both original degrees are odd, so the minus sign is required before reducing the second argument modulo \(V\).
FLINT computes these resultants exactly; the first four are also checked against the unreduced layer polynomial in the original argument order.

The complete exact integers are regenerated in `signed_filters.json`.
The program checks the sign vector \((1,1,1,1,1,0,1,0)\), with one denoting a negative norm.
Thus the first five layers have uniform negative-sign parity, while inclusion of layer six destroys that parity condition permanently for this fixed single filter.
The general significance of this condition, and the paired-filter alternative, are proved in the linked exploration rather than inferred from this finite table.

## Deterministic integral unit rectifiers

At \(p=81\), the trace order is \(\mathcal O=\mathbb Z[t]/B_{40}(t)\).
The signature columns are ordered as the constant unit \(-1\), followed by \(T_a/T_{3^{v_3(a)}}\) for ascending \(1\le a\le40\), omitting \(a=3^{v_3(a)}\).
These are 37 columns.
Every quotient and its inverse are formed by exact cyclic multiplication and coefficientwise division by two using the [retained inverse identity](readme.md#cyclic-arithmetic).
The program verifies the two-sided unit product in the integral quotient.
The quotient signs are exact integer comparisons of angles with cosine zeros.
The target filter signs are certified by 512-bit Arb evaluations at all 40 nodes; no interval containing zero is accepted.
Gaussian elimination over \(\mathbb F_2\), in the declared column order, has rank 37 and determines the selected columns.

For the single filter \(V_1=V\), the result is the explicit unit
\[
 q=-\prod_{a\in A}\frac{T_a}{T_{3^{v_3(a)}}},\qquad
 A=\{6,10,11,12,13,17,18,23,25,28,29,30,34,37,38\}.
\]
The fractions denote integral elements of this quotient, as checked by their native multiplication identities.
The multiplier \(u=qV_1\) is strictly positive at all nodes and has exact absolute norm 163.
The paired construction applies the same declared elimination rule to the signs of \(V_1V_2\); its complete selected columns and word are regenerated by `construct([1, 2])`.
It gives another strictly positive multiplier with norm \(163^2\).

## Nonsquare certificates and the supplied inputs

The program uses the primitive order-81 root \(4\bmod163\), lifted to \(7665\bmod163^2\) by the explicit one-step Hensel formula.
It checks the order condition and evaluates \(B\) at each resulting primitive trace, obtaining zero modulo \(163^2=26569\).
For the single multiplier, the trace at primitive index 8 is 15707 and the multiplier value is 978 modulo 26569.
This value is divisible by 163 and not by \(163^2\), so it cannot be a square modulo \(163^2\).
Evaluation at that trace is a ring homomorphism from \(\mathcal O\), proving that the multiplier is not an integer square in \(\mathcal O\).
Its nonsquare integer norm 163 is a second proof for the single-filter case.
For the paired multiplier the corresponding witnesses are indices 4 and 8, traces 9866 and 15707, and values 489 and 14670 modulo 26569.
Both values again have exactly one factor of 163, proving nonsquareness despite the paired multiplier's square total norm.

The existing balanced base is reconstructed without replaying descent:
\[
             h_*=h_{0,81}U_2^6U_1^{-1}(T_3/T_{15})^2,
             \qquad U_a=2+T_a.
\]
Its exact norm is 32 and its moments are \((K,L)=(-3,10)\), matching the [balanced control](balanced.md).
The new input is \(h_{\rm new}=h_*u\).
It retains the same strict terminal cut of length nine because \(u\) is positive at every node.

Neither input meets a prescribed two-moment target.
The program records the exact endpoint values but computes no whole Mahler measure.
These large energies are a limitation of the canonical rectifiers, not evidence that every positive-unit adjustment of their new square classes fails.
Since \(h_*\) is nonzero on every component, cancellation proves that neither supplied input can equal \(h_*v^2\) for an integer element \(v\) of the original trace order.

<a id="reproduction"></a>
## Reproduction and the read-only construction interface

Run with Python, SymPy, NumPy and python-flint, the dependencies of the imported exact cyclic helpers:

~~~text
python -B mathematics/computations/programs/Yin_J_G0154/signed_filters.py
~~~

The successful run used the existing Python 3.14.7, SymPy 1.14.0 and python-flint 0.9.0 environment.
It writes `mathematics/computations/outputs/Yin_J_G0154/signed_filters.json` with all eight signed norms, exact unit words and inverses, multiplier words, supplied words, moment data and modular witnesses.
No generated input file is read.
The importable call `construct([1])` independently reconstructs the prescribed single-filter input and returns `input_word`, `rectifier_word`, `positive_multiplier_word`, `input_norm` and the other exact data above.
`construct([1, 2])` supplies the separately fixed paired control.
These functions perform no rebalancing or lattice enumeration.
The checks are author-level local construction checks, not an independent formal review.
